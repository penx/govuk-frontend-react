# govuk-frontend-react

[govuk-frontend](https://github.com/alphagov/govuk-frontend) as React components.

This is a direct port: each component renders the same HTML as govuk-frontend's own Nunjucks macro, and this is checked against every fixture that govuk-frontend publishes. Styles and JavaScript come from govuk-frontend itself.

It currently ports **govuk-frontend 6.6.0**. More opinionated components, and components govuk-frontend doesn't provide, belong in [govuk-react](https://github.com/govuk-react/govuk-react), which builds on this package.

> Work in progress. See [Status](#status) for what's ported so far.

## Install

```sh
npm install govuk-frontend-react govuk-frontend react
```

Requires React 19 or later.

Load govuk-frontend's styles as its [documentation](https://frontend.design-system.service.gov.uk/) describes, for example:

```scss
@use 'govuk-frontend';
```

## Usage

```tsx
import { Button, Fieldset, Label, Hint, ErrorMessage } from 'govuk-frontend-react';

<Fieldset legend={{ children: 'What is your address?', isPageHeading: true, size: 'l' }}>
  <Label htmlFor="postcode">Postcode</Label>
  <Hint id="postcode-hint">For example, SW1A 2AA</Hint>
  <ErrorMessage id="postcode-error">Enter a postcode</ErrorMessage>
  …
</Fieldset>

<Button variant="secondary">Save as draft</Button>
<Button href="/start" start>Start now</Button>
```

## Conventions

Common conventions used when rewriting the Nunjucks templates.

### BEM

When looking at govuk-frontend BEM class names:

- Blocks become exported components.
- Elements become subcomponents, exported as a property of the main component.
- Modifiers become props of the component or subcomponent.

For example, a class name of `govuk-my-block__my-element--my-modifier` implies:

- There is a component `<MyBlock />`, available from `import { MyBlock } from 'govuk-frontend-react'`, that sits at `src/{type}/my-block/`.
- There is a subcomponent `<MyBlock.MyElement />`.
- `<MyBlock.MyElement />` accepts a prop `myModifier`.
- `{type}` is `objects` or `components`, following govuk-frontend's ITCSS layers.

So `govuk-fieldset__legend--l` is `<Fieldset.Legend size="l" />`, and `govuk-button--secondary` is `<Button variant="secondary" />`. Where a set of modifiers are alternatives, such as sizes or button variants, they share one prop.

BEM convention class name exceptions:

- `govuk-label-wrapper`

### Props

Where React prop names differ from the Nunjucks macro option names:

| Nunjucks             | React                                                              |
| -------------------- | ------------------------------------------------------------------ |
| `element`            | `as`                                                               |
| `attributes`         | rest props                                                         |
| `text`               | `children`                                                         |
| `html`               | `children`                                                         |
| `caller`             | `children`                                                         |
| `classes`            | `className`                                                        |
| `describedBy`        | `aria-describedby`                                                 |
| `for`                | `htmlFor`                                                          |
| `isStartButton`      | `start`                                                            |
| `legend`, and others | the content, or a props object for the subcomponent (see Fieldset) |

The full mapping for each component is in [`tests/nunjucks`](tests/nunjucks), which the parity tests use to render govuk-frontend's fixtures. It doubles as a guide for moving from Nunjucks to React.

### Class names

Every component takes a `classNames` lookup that replaces govuk-frontend class names with your own, for example the class names generated by CSS Modules or CSS-in-JS:

```tsx
<Button classNames={{ 'govuk-button': styles.button }}>Save</Button>
```

Class names without an entry are rendered unchanged.

## HTML parity

`npm run parity` renders every govuk-frontend fixture for each ported component and compares it with govuk-frontend's Nunjucks output. The comparison is on the parsed HTML: attribute order, class order and formatting whitespace are ignored, but elements, attributes, text and the whitespace between inline content must match. A fixture can only be skipped by listing it in [`tests/known-differences.ts`](tests/known-differences.ts) with a reason.
